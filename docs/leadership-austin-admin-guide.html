Leadership Austin Guide

A practical guide to monthly newsletter editions and subscriber event suggestions.

Use the Leadership Austin admin only. Confirm the address before making changes. Austin and Leadership Austin are separate sites with separate content and subscriber lists. https://leadershipaustin.irl.group/admin

1 · Sign in

  1. 1Enter the Leadership Austin admin email and complete the security check.
  2. 2Select Send login code, then enter the six-digit code sent to that email. If the page offers password sign-in instead, use the configured admin password.
  3. 3Select Log Out when finished, especially on a shared computer.

2 · Create a newsletter edition

  1. 1Create Newsletter Edition: create a draft. Its date is an internal anchor; public subject lines stay focused on upcoming events rather than a week or Sunday schedule.
  2. 2Generate from Event Sources: paste up to ten event-listing URLs. For Leadership Austin, the tool checks a rolling 30-day window from the selected start date. Review every date, remove out-of-range events, and add results to an unsent edition or create a new one.
  3. 3Add event or spotlight: use a source URL to auto-fill details, then review the title, event date, venue, description, category, and link before saving.
  4. 4Alumni Happenings: add a one-time event or community story to the selected edition. Choose the target edition before adding it.

3 · Review before sending

  1. 1Expand the edition row and check every event title, date, time, venue, category, and link. Remove duplicates or past events only after review.
  2. 2Use Draft to me to inspect the actual email. Check the complete edition and the production-status warning before any subscriber-wide send.
  3. 3Send to all emails the edition to active subscribers after a confirmation step. Approving a subscriber suggestion does not send an email.
Browser-only saves: source URLs, spotlight forms, and the Alumni Happenings “Save draft” button are remembered only in this browser. Use the form’s Add button to commit newsletter content.

Leadership Austin event tools

Subscriber event suggestions

Active subscribers can suggest public events from the full edition page. Suggestions remain unpublished until an admin reviews them.

  • At the top of Newsletter Editions, review the date, venue, description, submitter, and public event link.
  • Select Approve or Reject. Approval adds the event to the Leadership Austin site and future newsletter editions; it does not send an email.
  • The form accepts event suggestions, not newsletter copy or story submissions.

Admin-added upcoming events

Use the Leadership Austin event list to add an event directly to the public upcoming-events list.

  • Required: title, start date and time in Austin Central Time, venue, category, source name, person or team to credit, and description.
  • The visitor-facing date label is created from the start time. End time, venue address, organizer, and event link are under More details.
  • Archive removes an event from the active public list without deleting its record.

Alumni Happenings

Add a one-time event or community story to one selected newsletter edition. This is separate from the persistent upcoming-events list.

  • Choose the edition, then select Event or News.
  • Enter a title and description. Add a date and venue for events, and a source link or link label when useful.
  • Save draft stores the form in this browser only. Select Add event or Add news to add it to the edition.

Other admin tabs

  • Subscribers List: see active and unsubscribed status.
  • Settings: update newsletter name, admin email, categories, colors, and brand images.
  • Superconnector: review engagement points, challenges, and badges.
  • The Carpoolers tab is not part of the Leadership Austin admin.

Send carefully

Draft to me

Sends a test email to the admin address in Settings. It does not go to subscribers. Use it to check the rendered subject, links, and event details.

Send to all subscribers

Emails the selected edition to active subscribers after confirmation. Review the edition and production status first.

Preserve sent editions. Put new content in an unsent edition. For an explicitly requested correction to a sent event, make only that targeted change rather than replacing the issue. Deleting an edition removes it and its events. Use Archive for a single persistent event.
